IF SOMETHING BREAKS
==============================================================
If app import fails after any step:
  python -c "import traceback; from app.main import app" 2>&1 | head -30
  Fix the import or syntax error shown, then re-verify before proceeding.

If a test breaks that was passing before:
  Read the error — it's almost always a broken import caused by a file you just moved or created
  Find the file with the broken import using the traceback
  Fix the import to point to the correct new location
  Re-run pytest until green. Do NOT move to the next step while tests are red.

If alembic autogenerate produces an empty migration (no op.create_table in upgrade()):
  The model is not imported in alembic/env.py — open env.py and add:
    import app.modules.clients.model
    import app.modules.csp.model
    import app.modules.compliance.model
  Then regenerate the migration.

If alembic upgrade fails with "table already exists":
  The table was created by the original baseline migration.
  Open the new migration file and remove the op.create_table() for that table.
  Only include columns or constraints that are genuinely new.

If MarianMT download fails due to network restrictions:
  The model download script must still be created — just log a clear message:
    "MarianMT model unavailable in this environment. Download manually from:
     https://huggingface.co/Helsinki-NLP/opus-mt-en-sn
     Place in ~/.cache/huggingface/transformers/"
  The graceful fallback in the pipeline (TranslationResult.model_available=False) handles
  the runtime case — the script failure does not block Phase 2 completion.

If scripts/seed_knowledge_base.py --dry-run fails because ChromaDB is not running:
  In dry-run mode, the script must NOT attempt to connect to ChromaDB at all.
  Add a check: if dry_run is True, skip the ChromaDB client initialisation entirely
  and just print what would be ingested.
